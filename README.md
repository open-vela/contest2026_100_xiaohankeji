# <小涵打砖块>

## 一、作品简介
<小涵打砖块是一款基于 openvela 快应用框架开发的手表体感游戏。用户通过倾斜手腕控制挡板击碎砖块，游戏结束后展示时长与估算消耗热量，让用户在碎片时间完成一次“手腕微运动”。它解决了手表端娱乐内容稀缺、触屏操作体验差、游戏缺乏健康价值三个痛点，亮点在于用 IMU 体感交互替代触屏，并通过三级数据处理链在低算力手表上实现流畅控制。>

## 二、选题方向
<快应用 / 手表应用创新 本项目围绕智能手表的典型使用场景，利用设备内置IMU传感器实现体感交互，验证了体感游戏在手表端的可行性与体验优势，属于面向可穿戴设备的应用创新。>

## 五、AI Coding 使用说明

本作品在开发过程中借助 AI 辅助完成，形成了“需求描述 → AI 生成 → 真机验证 → 反馈修正”的协作模式。

### 各环节 AI 协作情况

| 环节 | AI 使用方式 | 实际帮助 |
| :--- | :--- | :--- |
| **需求拆解** | 描述游戏玩法，AI 帮助拆解为模块清单（UI、物理引擎、体感控制、数据持久化） | 快速明确开发范围，避免遗漏 |
| **方案设计** | 询问技术选型（传感器 API 调用方式、滤波算法选型） | AI 提供了滤波方案对比，帮助确定一阶低通滤波 + 死区的三级处理链 |
| **编码** | 描述界面需求，AI 生成 `.ux` 文件中的 `<template>` 结构和传感器订阅样板代码 | 大幅减少重复性布局和样板代码的编写时间 |
| **调试** | 将编译/运行时报错信息粘贴给 AI | 快速定位错误原因（如权限声明缺失、生命周期管理遗漏） |
| **文档** | AI 辅助生成技术报告框架和 Skill 说明 | 提升文档编写效率，保证结构完整 |

### AI 对开发效率与质量的实际帮助

- 将重复性编码工作（UI 布局、API 样板代码）从数小时缩短到数十分钟
- 通过 AI 快速验证算法方案，减少了从零搜索和试错的时间
- 报错时 AI 能快速指出问题方向，缩短了排查时间
- 在 AI 辅助下，能把更多精力放在体感手感调优和交互设计上

约 40%（AI 生成后由本人逐行理解并修改调整）。
